# Quickstart: 集成外部文件与数据存储

## 目标

验证 HomeHoney 已具备：

1. 可编辑的外部文件服务与数据服务连接配置
2. 文件性质资源通过外部文件服务完成列表、上传、下载与状态识别
3. 非文件业务数据通过 MongoDB 完成 CRUD
4. 远端失败反馈清晰，不会误导用户为“本地缓存成功”

## 建议实施顺序

### 1. 准备默认连接配置
- 在应用中打开设置页的存储配置入口
- 录入或确认文件服务地址
- 录入或确认 MongoDB 连接信息
- 保存配置并执行一次连接校验

### 2. 验证配置持久化
- 关闭应用并重新打开
- 再次进入存储配置入口
- 确认最新保存的配置仍然存在且处于激活状态

### 3. 验证文件性质资源流程
- 进入资料模块
- 查看保险合同或说明书列表
- 新增一条文件性质资源并上传文件
- 保存后重新打开详情，确认文件元数据与下载入口都存在
- 执行下载或打开原文件，确认文件来自外部文件服务

### 4. 验证非文件数据 CRUD
- 进入冰箱贴、备忘录、提醒或设置任一非文件模块
- 创建一条新记录
- 返回列表并确认可见
- 修改该记录并确认更新结果
- 删除该记录并确认列表不再展示

### 5. 验证一致性与异常反馈
- 人为让文件服务或数据服务不可达
- 重试一次文件上传、文件下载或非文件数据保存
- 确认页面展示的是明确错误或待同步状态，而不是空白成功提示
- 恢复服务后再次执行操作并确认状态恢复正常

### 6. 验证远端失败反馈
- 在服务可达时先访问至少一条资料记录与一类非文件列表
- 断开远端服务后重新进入相同页面
- 确认应用给出明确失败提示，而不是伪装成读取了本地持久化缓存

## 手动验收脚本

### 场景 A：配置切换
1. 使用默认本地连接完成一次成功保存
2. 将文件服务地址改为另一地址或故意错误地址
3. 验证保存前校验与保存后错误反馈符合预期
4. 改回正确地址后再次验证能力恢复

### 场景 B：保险合同文件上传与下载
1. 打开保险列表
2. 创建或编辑一条保险合同记录
3. 上传一个真实文件
4. 保存并返回详情
5. 验证附件状态显示为可用
6. 下载该文件并确认能成功打开

### 场景 C：说明书列表与缺失文件提示
1. 打开说明书列表
2. 读取至少一条记录的详情
3. 人为删除对应远端文件或模拟文件缺失
4. 重新进入详情
5. 验证页面提示文件不可用，而不是继续显示可下载成功

### 场景 D：非文件数据 CRUD
1. 在冰箱贴或备忘录页面创建新记录
2. 刷新页面并确认仍可查询到该记录
3. 修改标题或内容并保存
4. 再次读取确认变更已生效
5. 删除该记录并确认列表中消失

### 场景 E：远端失败与同步状态
1. 在服务正常时浏览文档列表和提醒列表
2. 关闭文件服务或 MongoDB 服务
3. 再次进入相同页面
4. 验证页面不会伪装成已经从本地持久化恢复数据
5. 验证页面明确标注当前为失败或待修复状态

## 完成定义

当以下条件全部满足时，本特性视为设计落地成功：

- 应用内可以保存并复用文件服务与数据服务连接配置
- 文件性质资源的文件本体由外部文件服务管理
- 结构化业务数据由 MongoDB 持久化并支持 CRUD
- 元数据与文件本体之间存在可追踪的引用关系与一致性状态
- 外部服务失败时，页面能给出明确反馈，不伪装成本地缓存成功
- 文档与验收步骤足以让团队独立重复上述验证

## 调试与错误定位

当应用出现启动期或运行期异常时，按以下顺序定位：

1. 直接查看应用内错误边界页面，确认是否已经显示异常详情
2. 查看 Rider / VS Code 的 Debug Console 或调试输出窗口
3. 重点检查是否仍有代码尝试把运行时数据写入应用包内部只读路径
4. 若是远端服务问题，分别验证 FileBrowser 与 MongoDB 连接是否仍可访问
