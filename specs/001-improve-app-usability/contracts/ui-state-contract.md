# UI State Contract: Improve App Usability

## 1. 适用范围

本契约定义以下用户可见页面在实现后必须满足的统一交互状态：

- 说明书新增/编辑、保险新增/编辑、备忘录新增/编辑、冰箱贴新增/编辑
- 保险详情、说明书详情中的附件区域
- 资料列表、提醒中心、搜索结果页

## 2. 表单交互契约

### 2.1 新增表单初始状态

| 页面类型 | 初始字段策略 | 必须满足 |
|----------|--------------|----------|
| 说明书 | 关键文本字段为空，需用户主动填写；非文本字段显示“未选择”语义 | 不得自动展示误导性业务内容 |
| 保险 | 保单名称、保险公司、联系人等字段为空；日期/分类需显式确认 | 不得让用户误以为默认值已被确认 |
| 备忘录 | 标题、内容为空；可选属性显示中性未确认状态 | 必填字段清晰可识别 |
| 冰箱贴 | 标题、内容为空；视觉样式若有默认渲染，不得等同于已确认业务选择 | 不得因视觉默认值掩盖必填信息 |

### 2.2 表单校验反馈

| 触发时机 | 页面行为 | 不允许发生 |
|----------|----------|------------|
| 用户点击保存且缺少必填项 | 页面内显示明确错误提示并阻止保存 | 仅写入调试日志、不提示用户 |
| 输入只有空白字符 | 视为无效输入并提示修正 | 被当作有效内容保存 |
| 仅部分字段有问题 | 保留其他有效输入 | 清空整张表单 |
| 历史记录字段为空 | 显示统一缺省文案 | 出现裸空白、null 字样或技术性占位符 |

## 3. 附件区域契约

### 3.1 展示字段

当资料存在附件或附件元数据可用时，附件区域必须按优先级展示：

1. 文件名
2. 文件大小
3. 最后同步时间
4. 当前附件状态说明

### 3.2 状态语义

| 状态 | 用户可见表现 | 后续动作 |
|------|--------------|----------|
| `NoAttachment` | 明确提示“暂无附件”或等价语义 | 可继续上传 |
| `AttachmentAvailable` | 展示文件名、大小、最后同步时间 | 可下载/替换 |
| `AttachmentMetadataPartial` | 展示已有字段，并对缺失字段标注“未知”或“未同步” | 可刷新或重新上传 |
| `AttachmentSyncUnknown` | 提示状态待确认 | 可重试获取或重新同步 |
| `AttachmentUnavailable` | 明确提示附件当前不可用 | 不得误导用户直接下载成功 |

## 4. 可重试列表契约

### 4.1 通用页面状态

| 状态 | 资料列表 | 提醒中心 | 搜索页 |
|------|----------|----------|--------|
| `Loading` | 显示加载反馈 | 显示加载反馈 | 显示加载反馈 |
| `Ready` | 显示结果列表 | 显示提醒列表 | 显示分组搜索结果 |
| `Empty` | 显示明确空状态 | 显示暂无提醒 | 显示无匹配结果 |
| `Error` | 显示失败反馈 + 重试按钮 | 显示失败反馈 + 重试按钮 | 显示失败反馈 + 重试按钮 |
| `Retrying` | 保留当前上下文并显示处理中 | 保留当前上下文并显示处理中 | 保留当前上下文并显示处理中 |

### 4.2 重试行为

- 点击“手动重试”后，页面必须重新发起当前读取请求。
- 重试过程中不得强制用户离开当前页面。
- 如果页面存在上一次成功数据，失败时应优先保留已显示数据，并补充失败提示。
- 重试成功后必须清除失败状态并刷新结果。
- 重试失败后必须保持页面可交互，并继续显示可理解反馈。

## 5. 统一反馈契约

- 成功、失败、空状态、处理中状态的表达方式必须在主要页面中保持一致。
- 面向用户的反馈不得直接暴露：
  - Mongo 集合名
  - FileBrowser 原始路径
  - 底层驱动异常文本
  - 仅面向开发者的技术细节
- 单个模块失败时，不得导致页面上其他已成功获取的信息全部消失。

## 6. 验收映射

- 本契约对应 [spec.md](../spec.md) 中的 FR-001 至 FR-016。
- 若实现无法满足上述状态语义，应视为本特性未完成。
