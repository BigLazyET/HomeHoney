# Quickstart: Improve App Usability

## 1. 目标

验证 HomeHoney 在本特性落地后满足以下要求：

- 新增/编辑说明书、保险、备忘录、冰箱贴时，不再出现误导性默认值
- 缺省显示、必填提示、空值处理和异常反馈在主要页面中保持一致
- 附件区域能展示文件名、文件大小和最后同步时间，或明确的缺省状态
- 搜索、提醒和资料列表在读取失败后可页面内手动重试
- Mongo 集合索引已完成初始化，可支撑后续列表读取与检索扩展

## 2. 前置条件

- 已安装 .NET 10 SDK
- 本地 MongoDB、FileBrowser 与 `HomeHoney.Api` 可正常启动
- 解决方案包含：
  - `HomeHoney`
  - `HomeHoney.Api`
  - `HomeHoney.Tests`
  - `HomeHoney.Api.Tests`

## 3. 建议验证顺序

### 3.1 自动化验证

1. 构建后端：`dotnet build HomeHoney.Api/HomeHoney.Api.csproj`
2. 构建共享客户端逻辑：`dotnet build HomeHoney/HomeHoney.csproj -f net10.0`
3. 运行后端测试：`dotnet test HomeHoney.Api.Tests/HomeHoney.Api.Tests.csproj -v minimal`
4. 运行客户端测试：`dotnet test HomeHoney.Tests/HomeHoney.Tests.csproj -v minimal`

**重点关注**：
- 表单空值/必填校验回归
- 附件元数据显示回归
- 列表失败后的重试行为回归
- Mongo 索引初始化不破坏现有读写流程

### 3.2 手动验收

## 4. 场景 A：表单默认值与必填提示

1. 进入说明书新增页
2. 观察设备名称、品牌、型号、日期、摘要等字段的初始状态
3. 直接点击保存
4. 仅填写部分字段后再次保存
5. 对保险、备忘录、冰箱贴重复同样验证

**预期结果**：
- 页面初始不出现误导性业务默认值
- 必填项缺失时，页面内直接提示并阻止保存
- 用户已填写的其他内容不会因一次校验失败而丢失
- 空白字符、仅分隔符等输入会被识别为无效输入

## 5. 场景 B：历史空值与缺省显示

1. 打开一条缺失部分字段的历史记录
2. 进入详情页和编辑页
3. 观察空字段的展示方式

**预期结果**：
- 页面使用统一缺省文案或状态提示
- 不出现裸空白、技术性占位符或异常崩溃
- 用户可继续编辑并补全缺失数据

## 6. 场景 C：附件元数据显示

1. 打开一条已上传附件的保险或说明书详情
2. 检查附件区域是否展示文件名、文件大小、最后同步时间
3. 上传新附件后再次查看详情
4. 打开一条无附件记录，再观察附件区域

**预期结果**：
- 有附件时，三类元数据可见且内容与最新状态一致
- 无附件时，页面显示明确的未上传提示而不是空白区块
- 元数据部分缺失时，页面能显示“未知/未同步”等缺省状态

## 7. 场景 D：手动重试

1. 让 `HomeHoney.Api` 保持可用，但临时制造对应页面读取失败条件
2. 打开资料列表、提醒中心和搜索页
3. 确认页面显示失败反馈与“手动重试”按钮
4. 恢复服务后点击重试

**预期结果**：
- 每个页面都能区分“暂无内容”和“加载失败”
- 重试发生在当前页内，不要求退出或重启应用
- 重试成功后刷新结果；失败时保留上下文与反馈

## 8. 场景 E：代码健壮性与异常隔离

1. 在各主要页面执行读取、保存、上传、下载等动作
2. 抽样验证出现单模块失败时首页或其他区域是否仍可正常显示
3. 检查失败反馈是否保持用户可理解语义

**预期结果**：
- 单个模块失败不会导致整页可用信息全部丢失
- 页面反馈不会暴露 Mongo 集合名、下游路径或底层驱动异常
- 失败状态可被用户理解并继续操作

## 9. 场景 F：Mongo 索引初始化

1. 启动 `HomeHoney.Api`
2. 确认索引初始化流程执行成功
3. 对保险、说明书、冰箱贴、备忘录、偏好、成员、空间等集合执行基础读取与写入
4. 抽样验证列表排序与常见读取路径仍正常返回

**预期结果**：
- 索引创建可重复执行且不影响已有数据
- 常见列表读取、详情读取和保存流程不因索引初始化失败而隐性退化
- 后续查询与检索扩展具备明确的索引基础

## 10. 回归检查

- 首页摘要仍可加载主要模块
- 首页单个模块失败时，其余模块仍可继续显示
- 资料列表、详情、新增/编辑流程仍可用
- 冰箱贴与备忘录流程仍可用
- 搜索和提醒聚合结果仍能显示
- 失败页面可在当前页执行“手动重试”
- 保险与说明书详情可看到附件文件名、大小与最后同步时间
- 设置与后端连接流程不受本特性破坏

## 11. 实施完成后关注点

- 历史脏数据仍可能缺少摘要、标签或附件元数据，页面应稳定显示缺省文案
- 若本地 Mongo 未配置，后端会跳过索引初始化并记录提示日志；这不会阻止基础 API 启动
- 若下游文件服务不可用，附件区域应显示同步失败或未上传状态，而不是空白区域
