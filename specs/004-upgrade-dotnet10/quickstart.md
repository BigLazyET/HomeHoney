# Quickstart: 升级到 .NET 10

## 目标

验证 HomeHoney 已完成 .NET 10 升级，并保持现有主流程与多平台构建连续性。

## 建议实施顺序

### 1. 统一运行时基线
- 更新仓库 SDK 锁定到 .NET 10
- 统一主应用与测试项目目标框架
- 确认 MAUI 工作负载可与新 SDK 协同工作
- 当前优先使用仓库已验证的 `10.0.102` SDK 补丁版本

### 2. 修复工程与依赖兼容性
- 处理新 SDK 暴露出的工程配置差异
- 处理目标平台 TFM 与最低平台版本的兼容问题
- 确认测试工程引用链仍可正常工作

### 3. 执行验证链路
- 还原依赖与工作负载
- 构建解决方案
- 运行测试项目
- 抽样验证首页、欢迎流、资料、冰箱贴、提醒与设置入口

### 4. 同步协作文档
- 更新 README 中的 SDK 前置条件、构建命令和平台说明
- 记录升级后必须执行的验证步骤
- 确保后续成员不依赖口头说明即可接手

## 手动验收脚本

### 场景 A：环境准备
1. 在开发机安装 .NET 10 SDK
2. 打开仓库并确认 SDK 锁定已指向新基线
3. 执行 `dotnet workload restore` 恢复当前项目依赖与 MAUI 工作负载
4. 验证不出现“当前 SDK 不支持目标框架”的错误

### 场景 B：解决方案构建
1. 在仓库根目录执行标准构建命令
2. 验证主应用工程成功构建
3. 验证测试工程成功构建
4. 若 iOS / Mac Catalyst 失败，先确认 Xcode 是否达到 26.2
5. 若 Android 失败，先确认 Java 是否达到 17+
6. 记录失败范围与原因

### 场景 C：自动化验证
1. 运行测试项目或解决方案测试命令
2. 验证现有单元测试与组件测试全部通过
3. 若存在失败，确认是否由 SDK/TFM/依赖变更引起

### 场景 D：核心流程抽样
1. 启动应用
2. 进入首页
3. 进入欢迎引导、资料、冰箱贴、提醒和设置页面
4. 验证页面可进入且主要导航正常
5. 验证最近一次实现的删除与返回能力未因升级退化

### 场景 E：文档对齐
1. 查阅 README 的前置条件与构建说明
2. 按说明重新执行一遍环境准备与验证
3. 验证文档中的版本、命令与实际结果一致

## 完成定义

当以下条件全部满足时，本特性视为设计落地成功：

- 仓库默认 SDK 与项目目标框架已统一到 .NET 10
- `dotnet workload restore` 可在当前仓库根目录成功完成
- 主应用与测试工程都能成功完成标准构建与验证
- 现有目标平台范围仍具备可验证构建能力
- 首页、欢迎流、资料、冰箱贴、提醒与设置等核心入口无明显回归
- README 与规范文档已能独立指导团队完成环境准备和验收
