# Feature Specification: App 页面结构与导航规划

**Feature Branch**: `002-app-page-structure`  
**Created**: 2026-03-10  
**Status**: Draft  
**Input**: User description: "帮我设计App的页面结构，其功能主要包括 欢迎和引导，保险(保险列表，详情，添加等)，家庭冰箱贴，家庭备忘录，说明书(功能同保险类似)，设置(暗黑和日间主题切换等)这些功能；帮我合理规划，并带入你自己的思考添加更多的场景和功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 欢迎引导与首页导航 (Priority: P1)

作为首次使用 HomeHoney 的家庭成员，我希望在打开应用后看到清晰的欢迎与引导流程，并快速理解首页和核心入口，这样我可以在几分钟内知道应用能做什么、下一步该去哪里。

**Why this priority**: 如果用户第一次打开应用时看不懂信息结构，就很难继续录入保险、说明书或备忘信息。欢迎引导和首页导航是所有后续模块的入口。

**Independent Test**: 首次启动应用，完成欢迎与引导流程后进入首页，验证用户能在不查看帮助文档的情况下找到保险、说明书、冰箱贴、备忘录和设置入口。

**Acceptance Scenarios**:

1. **Given** 用户首次启动应用且没有任何数据，**When** 用户进入应用，**Then** 系统展示欢迎页、核心功能介绍和进入首页的明确操作入口
2. **Given** 用户完成引导进入首页，**When** 用户查看首页，**Then** 系统展示统一导航结构、模块入口、最近事项摘要和空状态提示
3. **Given** 用户已完成首次引导，**When** 用户再次打开应用，**Then** 系统默认直接进入首页而不是重复展示完整引导

---

### User Story 2 - 保险与说明书资料管理 (Priority: P1)

作为家庭资料整理者，我希望用统一的信息结构管理保险和说明书，能够查看列表、详情、添加新资料，并根据到期时间、所属成员或空间位置快速筛选和查找。

**Why this priority**: 保险和说明书是应用最核心的长期价值来源，也是用户最常需要检索和维护的高价值家庭资料。

**Independent Test**: 分别进入保险和说明书模块，验证用户可以完成“浏览列表 → 查看详情 → 新增资料 → 返回列表”的完整闭环，并能看到合理的空状态和筛选入口。

**Acceptance Scenarios**:

1. **Given** 用户进入保险模块，**When** 用户查看列表页，**Then** 系统展示保险列表、筛选条件、搜索入口和新增入口
2. **Given** 用户打开某个保险详情页，**When** 用户查看详情，**Then** 系统展示保单名称、保障对象、关键日期、附件摘要和后续操作入口
3. **Given** 用户进入说明书模块，**When** 用户查看某个说明书详情，**Then** 系统展示设备名称、所属空间、型号信息、关联附件和快速定位信息
4. **Given** 用户需要录入新资料，**When** 用户点击新增入口，**Then** 系统提供结构化表单，帮助用户分别添加保险或说明书资料

---

### User Story 3 - 家庭冰箱贴与备忘录协作 (Priority: P2)

作为家庭成员，我希望像使用实体冰箱贴一样快速记录提醒、购物清单、待办和短消息，同时也希望有更正式的备忘录页面来整理长期事项。

**Why this priority**: 冰箱贴和备忘录让应用不仅能管理“静态资料”，还能承载“日常家庭协作”，提高打开频率和实际使用价值。

**Independent Test**: 进入冰箱贴和备忘录模块，验证用户可以分别完成快速创建、浏览列表、查看详情/展开内容、标记重要和删除或归档操作。

**Acceptance Scenarios**:

1. **Given** 用户进入家庭冰箱贴页面，**When** 用户查看内容，**Then** 系统展示便签墙式布局、优先级/分类标识和快速新增入口
2. **Given** 用户需要记录一条正式备忘，**When** 用户进入备忘录模块，**Then** 系统展示列表视图、分类方式和详情页入口
3. **Given** 用户在冰箱贴中记录临时事项，**When** 用户标记其为重要或待办，**Then** 系统将其在首页摘要或提醒中心中提升展示优先级

---

### User Story 4 - 搜索、提醒与家庭首页摘要 (Priority: P2)

作为经常需要“临时找资料”的用户，我希望在一个统一入口中看到即将到期的保险、需要处理的家庭备忘、最近添加的说明书，以及能够通过搜索快速找到目标内容。

**Why this priority**: 当数据逐渐增多时，单纯依赖模块跳转会增加使用成本。统一搜索和提醒中心是让应用长期可用的关键。

**Independent Test**: 在已有不同类型数据的前提下，验证用户可通过首页摘要和搜索入口，在一次查询中定位保险、说明书、冰箱贴或备忘录内容。

**Acceptance Scenarios**:

1. **Given** 系统中存在不同类型的家庭资料和提醒事项，**When** 用户进入首页，**Then** 系统展示最近事项、即将到期项目和推荐快捷操作
2. **Given** 用户输入关键词，**When** 用户执行搜索，**Then** 系统返回跨模块的搜索结果，并按内容类型进行区分
3. **Given** 某保险即将到期或某备忘设置了时间提醒，**When** 用户进入提醒中心，**Then** 系统集中展示待处理事项及其来源模块

---

### User Story 5 - 设置与个性化体验 (Priority: P3)

作为长期使用者，我希望在设置中管理主题模式、通知偏好、首页模块顺序和隐私相关选项，让应用更符合家庭成员的使用习惯。

**Why this priority**: 设置模块不会影响首次理解应用，但会显著影响长期留存、舒适度和家庭成员间的共用体验。

**Independent Test**: 进入设置页面，分别切换深色/浅色主题、调整提醒偏好并查看首页模块配置，验证变更会即时反映到相关页面。

**Acceptance Scenarios**:

1. **Given** 用户进入设置页，**When** 用户切换浅色、深色或跟随系统主题，**Then** 应用整体视觉风格同步更新
2. **Given** 用户希望减少打扰，**When** 用户调整提醒偏好，**Then** 系统允许分别控制保险到期提醒、说明书维护提醒和备忘事项提醒
3. **Given** 用户更常使用某些模块，**When** 用户调整首页模块顺序或可见性，**Then** 首页摘要区按新的优先级展示内容

### Edge Cases

- 用户首次进入某个模块且没有任何数据时，系统应展示明确的空状态说明、示例内容或下一步操作建议
- 用户录入内容过多时，列表页应仍能通过筛选、排序和搜索快速定位内容，而不是要求用户逐页查找
- 保险和说明书可能存在重复或高度相似的条目，系统应允许用户识别重复项并避免误操作
- 家庭冰箱贴与备忘录可能同时存在临时事项和长期事项，系统应提供足够清晰的区分方式
- 用户关闭通知权限后，提醒中心仍应在应用内展示待处理事项，而不是完全消失
- 用户切换主题模式时，当前页面应保持阅读连续性，不应导致用户迷失在新的导航层级中

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须（MUST）提供欢迎页与引导流程，用于向首次使用者解释应用定位、核心模块和推荐的起始操作
- **FR-002**: 系统必须（MUST）提供统一且稳定的一级导航结构，覆盖首页、资料管理、家庭冰箱贴、备忘/提醒、设置等核心入口
- **FR-003**: 系统必须（MUST）提供首页摘要页，集中展示最近资料、待处理提醒、快捷入口和空状态引导
- **FR-004**: 用户必须（MUST）能够在保险模块中浏览列表、查看详情、添加新保险资料、编辑资料并管理附件摘要信息
- **FR-005**: 保险列表必须（MUST）支持至少按状态、家庭成员、到期时间或类别进行筛选或排序
- **FR-006**: 保险详情页必须（MUST）展示与用户决策相关的关键字段，包括保障对象、关键日期、保障摘要、联系人或理赔入口提示
- **FR-007**: 用户必须（MUST）能够在说明书模块中浏览列表、查看详情、添加说明书资料，并按空间、设备类别或品牌进行整理
- **FR-008**: 说明书详情页必须（MUST）展示设备名称、所属空间、型号、关键日期、附件摘要和相关操作入口
- **FR-009**: 保险与说明书模块必须（MUST）共享一致的资料架构与交互逻辑，以降低学习成本，同时保留各自的字段差异
- **FR-010**: 系统必须（MUST）提供家庭冰箱贴模块，用于快速记录便签、购物事项、临时提醒和家庭留言
- **FR-011**: 系统必须（MUST）提供家庭备忘录模块，用于管理较长内容、长期事项、家庭规则或需要保留历史的记录
- **FR-012**: 用户必须（MUST）能够将冰箱贴或备忘录标记为重要、待办、已完成或归档，以支持家庭协作和后续跟踪
- **FR-013**: 系统必须（MUST）提供统一搜索能力，可跨保险、说明书、冰箱贴和备忘录返回结果，并清晰标识内容来源
- **FR-014**: 系统必须（MUST）提供提醒中心或待处理事项页，集中展示保险到期、说明书维护节点、家庭待办和重要备忘
- **FR-015**: 系统必须（MUST）支持从首页、提醒中心和搜索结果进入目标详情页，避免用户重复穿越多层页面
- **FR-016**: 设置模块必须（MUST）支持浅色主题、深色主题和跟随系统主题三种显示模式
- **FR-017**: 设置模块必须（MUST）支持管理通知偏好，包括保险、说明书和备忘事项的提醒开关或粒度控制
- **FR-018**: 设置模块应（SHOULD）允许用户管理首页模块顺序、可见性或默认展示优先级
- **FR-019**: 系统必须（MUST）为各主要模块提供清晰的空状态、首次使用提示和返回路径
- **FR-020**: 系统必须（MUST）在离线情况下保持主要浏览、录入、查找和查看能力可用，以符合家庭场景的即时查询需求
- **FR-021**: 系统应（SHOULD）支持家庭成员视角或归属信息，让用户能看出某条保险、备忘或说明书与哪位家庭成员或哪个空间相关
- **FR-022**: 系统应（SHOULD）在设置中提供隐私增强选项，如敏感信息显示策略或应用访问保护入口，以满足家庭共用设备场景

### Key Entities *(include if feature involves data)*

- **家庭主页模块（Home Module）**: 首页中可单独呈现的功能区块，如最近资料、即将到期、快捷操作、家庭留言摘要
- **家庭成员（Household Member）**: 家庭中的个人实体，可关联保险、备忘、提醒或设备归属
- **保险资料（Insurance Record）**: 一份保险相关记录，包含保单名称、保障对象、状态、关键日期、联系人、附件摘要等信息
- **说明书资料（Manual Record）**: 一份设备或产品说明书记录，包含设备名称、型号、品牌、所属空间、关键日期和附件摘要
- **家庭冰箱贴（Fridge Note）**: 用于快速记录短消息、提醒或购物事项的轻量条目，强调即时性与醒目展示
- **家庭备忘录（Memo）**: 用于保存较长、较正式或需要历史沉淀的信息条目，可包含分类、重要级别和完成状态
- **提醒事项（Reminder Item）**: 从保险、说明书、冰箱贴或备忘录中派生出的待处理事项，按时间、重要性和来源模块聚合展示
- **用户偏好（User Preference）**: 与主题、通知、首页布局和隐私展示相关的个性化设置

## Assumptions

- 首页采用“摘要 + 快捷入口”的方式，而不是承载全部列表内容，以减少首次进入的信息压力
- 保险与说明书虽然属于不同业务对象，但会共用相似的列表、详情和新增路径，以降低产品复杂度
- 家庭冰箱贴偏向短内容和高频使用，家庭备忘录偏向长内容和长期管理，两者需要并存而非二选一
- 搜索和提醒能力是对用户原始需求的合理扩展，因为随着家庭资料增加，查找和待办管理会成为高频场景
- 设置模块除主题切换外，还需要覆盖通知与首页个性化，才能支撑长期使用体验

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首次使用者能够在 2 分钟内完成欢迎引导并进入首页，且能识别至少 4 个核心模块入口
- **SC-002**: 用户从首页或一级导航出发，能够在不超过 2 次点击/触摸内进入保险、说明书、冰箱贴、备忘录或设置模块
- **SC-003**: 用户能够在不借助外部说明的情况下，于 3 分钟内完成一条保险资料或说明书资料的新增流程
- **SC-004**: 当系统中存在跨模块数据时，用户能够在 30 秒内通过首页摘要或搜索入口定位到目标内容
- **SC-005**: 所有一级模块均提供空状态文案、下一步行动提示和返回路径，不出现“空白页”或无解释页面
- **SC-006**: 用户切换主题模式后，首页、资料列表页、详情页和设置页均在当前会话中反映新的视觉模式
- **SC-007**: 提醒中心能够在同一页面中展示未来 30 天内需要关注的保险、说明书和家庭待办事项
