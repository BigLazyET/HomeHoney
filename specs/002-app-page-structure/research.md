# Research: App 页面结构与导航规划

## 决策 1：采用“底部一级导航 + 模块内二级页面”信息架构

- **决策**：一级导航固定为 `首页`、`资料`、`冰箱贴`、`提醒`、`设置` 五个入口；`保险` 与 `说明书` 作为 `资料` 模块内的二级分组，而不是各自占据一级 Tab。
- **理由**：
  - 一级导航数量控制在 5 个以内，更适合移动端底部导航。
  - `保险` 与 `说明书` 在用户心智中都属于“家庭资料”，共享列表、筛选、详情、录入等交互模型，合并后更利于统一设计。
  - 保留 `冰箱贴` 作为独立入口，可强化其“高频、轻量、家庭协作”的定位。
- **考虑过的替代方案**：
  - **6~7 个底部 Tab 平铺所有模块**：被否决，因为移动端拥挤且不利于触控。
  - **首页 + 全部功能放抽屉菜单**：被否决，因为会增加核心功能的发现成本。

## 决策 2：首页采用“摘要仪表盘”，不承载完整列表

- **决策**：首页只展示跨模块摘要：最近资料、即将到期、待处理事项、家庭留言摘要、快捷入口；各模块完整列表留在各自模块页。
- **理由**：
  - 首次进入应用时，首页应降低认知负担，而不是让用户直接面对大量内容。
  - 摘要仪表盘更符合家庭管理应用的“总览 → 进入模块处理”的使用节奏。
  - 有利于后续按用户偏好调整模块顺序和显示优先级。
- **考虑过的替代方案**：
  - **首页直接拼接所有模块列表**：被否决，因为长页面在手机上难以浏览，也不利于性能与信息分组。
  - **首页仅显示品牌欢迎页**：被否决，因为缺乏持续使用价值。

## 决策 3：保险与说明书共享“文档型页面模式”

- **决策**：保险和说明书统一采用 `列表页 → 筛选/搜索 → 详情页 → 新增/编辑页` 的页面模式，并共享“文档卡片、状态标签、附件摘要、关键日期”设计语言。
- **理由**：
  - 与宪章中的“文档模型驱动”一致。
  - 用户学习一次后即可迁移到两个模块，减少认知成本。
  - 便于后续抽象共用组件，如 `DocumentList`, `DocumentDetailSection`, `MetadataChipGroup`。
- **考虑过的替代方案**：
  - **保险与说明书完全独立设计**：被否决，因为会带来重复交互和重复组件。
  - **把说明书并入保险模块**：被否决，因为业务语义不同，字段需求差异明显。

## 决策 4：把搜索与提醒设计为跨模块能力，而不是模块内附属功能

- **决策**：统一搜索和提醒中心作为横切能力存在，结果聚合保险、说明书、冰箱贴、备忘录等多种内容。
- **理由**：
  - 用户真实场景通常不是“我要去哪个模块”，而是“我要找某个东西”或“我有什么待处理事项”。
  - 统一入口有利于后续接入本地索引、提醒调度和到期计算服务。
- **考虑过的替代方案**：
  - **各模块各自搜索和提醒**：被否决，因为会割裂用户心智并增加重复实现。

## 决策 5：欢迎引导只在首次进入时完整展示，后续保留轻量帮助入口

- **决策**：首次打开应用时展示欢迎/引导页，完成后默认进入首页；后续通过设置或首页空状态中的“再次查看引导”入口重新访问。
- **理由**：
  - 首次引导可以帮助用户理解模块结构和推荐的起始操作。
  - 重复强制展示完整引导会干扰长期使用者。
- **考虑过的替代方案**：
  - **每次启动都显示欢迎页**：被否决，因为影响效率。
  - **完全不做引导**：被否决，因为应用信息架构较丰富，首次使用成本较高。

## 决策 6：设置页除主题切换外，纳入通知、首页编排和隐私显示策略

- **决策**：设置页分为 `外观`、`提醒`、`首页布局`、`隐私与安全`、`关于与帮助` 五个分区，而不是只放主题开关。
- **理由**：
  - 主题切换只是视觉层设置，不足以支撑长期使用偏好管理。
  - 家庭共用设备场景需要隐私显示策略和敏感字段保护入口。
  - 首页模块排序是本功能信息架构的重要组成部分，应在设置中有明确归属。
- **考虑过的替代方案**：
  - **设置仅保留主题切换**：被否决，因为扩展性不足。

## 决策 7：UI 契约采用“页面与路由契约文档”形式，而不是 API 契约

- **决策**：本特性不涉及对外网络接口，`contracts/` 使用页面结构/导航契约文档记录路由、入口、页面职责与关键状态。
- **理由**：
  - 当前任务是信息架构与页面结构设计，不是外部服务接口设计。
  - 页面与路由契约能直接服务后续 UI 实施、组件拆分和任务分解。
- **考虑过的替代方案**：
  - **不生成 contracts/ 目录**：被否决，因为用户交互入口本身就是对最终用户暴露的契约。
